## 직접 증거

NPU 직접 증거로 인정한 자료:

- [x] **OVMS 서버 로그 (target_device=NPU)** — graph.pbtxt `device:"NPU"` (AUTO/폴백 아님), 모델 state `AVAILABLE`
- [x] **OpenVINO NPU plugin 로그** — `FULL_DEVICE_NAME: Intel(R) AI Boost`, `EXECUTION_DEVICES: NPU`, `NPU: Intel(R) AI Boost`
- [x] **PDH GPU Engine counter** — 추론 부하 중 `...luid_..0x11b60..engtype_compute` **88.1%** (ovms pid 28192), 동시 Arc GPU(0x116de) engtype_3d 1.5%
- [ ] 작업 관리자 NPU% 스크린샷 (미수집, 불요)
- [ ] 벤더 샘플 출력 (불요)
- [ ] ETW/perf trace (불요)

증거 설명:

```text
1) OpenVINO가 NPU를 디바이스로 인식하고, LLM 노드의 실행 디바이스가 NPU로 보고됨:
   - "Available devices for Open VINO: CPU, GPU, NPU"
   - NPU plugin: FULL_DEVICE_NAME: Intel(R) AI Boost, DEVICE_LUID 601b010000000000 (low 0x11b60),
     NPU_DRIVER_VERSION 1004509, EXECUTION_DEVICES: NPU
   - graph.pbtxt 의 device 가 "NPU" 로 하드코딩되어 있어 CPU/GPU 폴백 경로가 없음.
     (실제로 IR 누락 시에는 즉시 "Could not find a model" 로 실패했고, IR 확보 후에만 AVAILABLE 도달)

2) LUID 매핑이 OpenVINO 자체 로그로 확정됨:
   - 0x11b60 = Intel AI Boost (NPU)
   - 0x116de = Intel Arc B390 GPU
   추론 부하를 걸자 0x11b60(NPU) compute 엔진만 88.1% 로 치솟고 GPU(0x116de)는 1.5% 에 그침
   → silent CPU/GPU fallback 아님. NPU 실행 확정.

3) tok/s: usage 기반 stream decode 측정으로 37.23 tok/s (3회 일관). 게이트 기준 >5 tok/s 충족.
```

## 결론

### 합격 여부

**Partial** — Text 게이트 PASS, VLM 미검증.

- ~4B 모델(Qwen3-4B-Instruct-2507 INT4)이 Intel NPU에서 `> 5 tok/s`(실측 37.23) AND NPU 직접 증거 ≥1(실제 3종) → **Text 합격 기준 충족**.
- VLM(vision encode) 경로 미실행 → 전체는 Partial.

### 최종 모델/사이즈 결정

- Text: **Qwen3-4B-Instruct-2507 INT4 (sym, per-channel)** 확정. 37 tok/s로 짧은 번역에 충분. 더 작은 fallback(≤1.7B)은 필요 시 추가.
- Visual: 미정 (Qwen3-VL-4B 검증 후 확정).
- Vision encode: 미검증.

### 다음 Phase에 넘길 결정

- Phase 1 Text 엔진 백엔드: **OVMS(OpenVINO GenAI, device=NPU)**, base_url `http://127.0.0.1:8000/v3`, model `qwen3-4b-instruct-2507`.
- Phase 2 Visual 경로: **VLM NPU 적재·vision encode 검증 선결** 후 결정. 검증 실패/저속 시 경량 OCR + 소형 텍스트 LLM 경로(ADR-013)로 전환.

### 실패/위험 기록

```text
[갭] scripts/phase0/run_model_profile.ps1 의 `--Action pull` (ovms --pull --source_model <HF>)는
     원본 safetensors(BF16)만 받고 OpenVINO IR(.xml/.bin)로 변환하지 않는다. 그 상태로 serve 하면
     OVMS GenAI LLM 노드가 "Could not find a model in the directory" 로 실패.
     → 현재는 optimum-cli export openvino (INT4) 로 별도 변환해야 NPU serve 가능.
     → 후속: pull 스텝에 IR export(또는 OpenVINO 사전변환 repo pull)를 포함하도록 스크립트 보완 필요.
       또한 profile.runtime_model(qwen3-4b-instruct-2507)과 OVMS pull 디렉토리명(Qwen/Qwen3-4B-Instruct-2507)
       불일치 → serve 시 model_name/model_path 정합 필요.

[환경] optimum-cli export 시 한글(cp949) 콘솔에서 rich 진행바의 유니코드(•) 출력이 UnicodeEncodeError를

[리스크] NPU 전용 PDH counter set 부재 → NPU% 는 GPU Engine(engtype_compute, NPU LUID) 인스턴스로 관찰.
         FR-D4/D6 대시보드 구현 시 이 인스턴스 경로를 사용.
```
